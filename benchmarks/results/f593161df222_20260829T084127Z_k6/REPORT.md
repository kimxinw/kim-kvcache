# K6 固定页运行时与页面晋升盈亏平衡报告

## 范围

本报告记录可执行 Hetero-8/64 运行时与 Fixed-8/16/32/64 运行时之间的
K6 正式对比。对比覆盖采用相同工作负载定义和计时边界的 CPU 元数据路径
与 CUDA 数据路径。本报告不宣称实现了端到端模型服务加速。

|---|---|

| 驱动程序 | 560.94 |

且资源已完全释放。`SHA256SUMS` 覆盖本目录中的全部产物。

## CUDA 访问路径对比

下表使用 CUDA 事件平均延迟。当工作负载包含注意力计算时，
“访问”指 Gather 与参考注意力计算之和。

| 工作负载 | 变体 | Gather（µs） | Attention（µs） | 访问总计（µs） |
|---|---:|---:|---:|---:|
| Long | Hetero | 269.411 | 1,298.261 | 1,567.672 |
| Long | Fixed-8 | 664.320 | 1,685.256 | 2,349.576 |
| Long | Fixed-16 | 445.048 | 1,461.320 | 1,906.368 |
| Long | Fixed-32 | 330.629 | 1,352.189 | 1,682.818 |
| Long | Fixed-64 | 256.843 | 1,233.198 | 1,490.041 |
| Mixed | Hetero | 168.283 | 743.186 | 911.469 |
| Mixed | Fixed-8 | 323.922 | 901.989 | 1,225.911 |
| Mixed | Fixed-16 | 258.734 | 860.730 | 1,119.464 |
| Mixed | Fixed-32 | 204.147 | 778.110 | 982.257 |
| Mixed | Fixed-64 | 155.878 | 690.373 | 846.251 |

Hetero 相比 Fixed-8 降低了测得的访问成本，但在这个独立数据路径微基准中，
Fixed-64 仍然更快。Fixed-64 同时存在 K5 容量模型所记录的容量与碎片权衡。

## 页面晋升盈亏平衡

分析性重复访问模型仅基于测得的基础操作：

```text
净收益(N) = N * (Fixed8_访问成本 - Hetero_访问成本) - 页面晋升成本
```

页面晋升成本等于成功的页面晋升 CUDA 事件样本之和除以 20 次正式测量迭代。
该模型描述对同一段已晋升 KV 区域的重复访问，不是对端到端服务性能的预测。

| 工作负载 | 每次迭代的页面晋升（µs） | 相对 Fixed-8 的单次访问收益（µs） | 盈亏平衡点 |
|---|---:|---:|---:|
| Long | 819.403 | 781.904 | 2 次访问 |
| Mixed | 436.883 | 314.442 | 2 次访问 |
| Shared Prompt | 不适用 | -4.139 | 无页面晋升样本 |
| Fork/COW | 不适用 | -12.941 | 无页面晋升样本 |

已登记的 Shared Prompt 和 Fork/COW 工作负载路径不会执行页面晋升事务。
因此，这两行被明确标记为不适用，而没有根据无关样本进行外推。
完整的 1/2/4/8/16/32/64/128 次重复访问曲线位于
`promotion_break_even_curve.csv`。

在两个可执行页面晋升的场景中，整个工作负载的单次访问吞吐量仍然较低：
Long 场景中 Hetero 为 202.82 requests/s，Fixed-8 为 230.55 requests/s；
Mixed 场景中 Hetero 为 334.35 requests/s，Fixed-8 为 420.54 requests/s。
因此，测得的盈亏平衡结果并不能证明单次访问或端到端加速。

## Nsight 性能剖析状态

Nsight 性能剖析受当前 WSL2 双 GPU 环境阻塞：

- Nsight Systems 2024.3.2 和 2025.2.1 均可采集报告容器，但导入时会因
  Quadro P4000 的 UUID 报错 `Unrecognized GPU UUID`，即使显式选择 RTX 3060
  也会如此。因此，CUDA 内核/API 汇总表为空。
- Nsight Compute 2024.3.2 和 2025.2.1 均能附加到基准程序，但随后在 device 0
  返回 `Unknown Error on device 0`。设备指标发现可以识别 RTX 3060，说明故障
  发生在开始采集时。

完整日志保留在 `profiling_attempts/` 中。在能够采集 CUDA 跟踪信息和性能计数器的
环境中重新运行案例分析之前，K6 必须保持未关闭状态；可选环境包括原生 Linux
或 GPU/驱动配置已修正的 WSL。

## 结论

K6 的固定页运行时矩阵和页面晋升盈亏平衡部分已经完成且可复现。
在测得的 Long 和 Mixed 场景中，页面晋升相对 Fixed-8 大约在两次重复
Gather+Attention 访问后摊平成本。目前没有端到端加速证据，Nsight 案例分析
是明确的剩余阻塞项。
